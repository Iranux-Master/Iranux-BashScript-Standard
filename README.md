# Iranux Bash Script Standard

**A lightweight metadata and verification standard for making Bash scripts readable, form-driven, and verifiable by Iranux.**

> Status: Draft v1.0  
> Target: Bash scripts executed through the Iranux application  
> Scope: Metadata, parameter discovery, input form generation, compatibility validation, embedded certification, and runtime end-marker detection

## 1. What Is Iranux Bash Script Standard?

**Iranux Bash Script Standard** is a simple, self-contained standard for adding structured metadata to Bash scripts.

It allows a Bash script to describe:

- what the script is;
- what user inputs it requires;
- what type each input has;
- which inputs are required;
- how those inputs should be displayed to the user;
- whether the script is compatible with Iranux;
- whether the script has been officially verified and signed by Iranux;
- whether the script reached its intended final execution point on the server.

The standard is designed for the **Iranux** application, a Windows-based tool that connects to Linux servers over SSH, runs Bash scripts remotely, streams live output, and displays results to the user.

---

## 2. Why This Standard Exists

Many Bash scripts ask for input interactively:

```bash
read -p "Enter domain: " DOMAIN
read -p "Install Nginx? Y/N: " INSTALL_NGINX
```

This works in a terminal, but it is difficult for a graphical application to understand:

- what inputs are needed;
- which inputs are required;
- what type each value should be;
- whether the value is a password, token, domain, port, or email;
- how to build a safe and clean form for the user;
- whether the script is compatible with the application.

Iranux Bash Script Standard solves this by letting the script describe its inputs with embedded JSON metadata.

Instead of guessing what a Bash script needs, Iranux can read the script and build a proper form automatically.

---

## 3. Core Design Philosophy

Iranux Bash Script Standard v1.0 is intentionally simple.

It is a:

```text
metadata and tagging standard
```

It is not a:

```text
Bash framework
workflow engine
configuration-management platform
package manager
Ansible replacement
cloud-init replacement
security hardening framework
```

The goal is not to rewrite Bash logic.

The goal is to make Bash scripts:

```text
discoverable
readable
form-driven
compatible with Iranux
verifiable by Iranux Validator
```

## 4. Script Status Levels

Iranux recognizes three script status levels.

### 4.1 Plain Bash Script

A normal Bash script with no Iranux metadata.

```text
Plain Bash Script
```

Meaning:

- Iranux cannot automatically discover structured parameters.
- The script may still run, depending on application policy.
- It is not Iranux Compatible or Iranux Verified.

---

### 4.2 Iranux Compatible

A Bash script with valid Iranux metadata and parameter definitions.

```text
Iranux Compatible
```

Meaning:

- Iranux can read the script metadata.
- Iranux can discover required parameters.
- Iranux can build a user input form.
- The script follows the Iranux metadata standard.
- The script is not officially signed.

---

### 4.3 Iranux Verified

A Bash script with valid Iranux metadata and a valid embedded certification block generated by the official Iranux Validator.

```text
Iranux Verified
```

Meaning:

- The script passed Iranux validation.
- The script was signed by Iranux Validator.
- The script has not changed after signing, assuming hash and signature validation succeed.

Important:

```text
Iranux Verified does not guarantee that the script will successfully install or configure software on every server.
```

It only means the script structure, metadata, parameter definitions, and Iranux compatibility were verified.

Actual runtime success still depends on the server environment, permissions, operating system, package manager, network access, and other conditions.

---

## 5. Main Concepts

An Iranux-compatible Bash script may contain these embedded blocks:

| Block | Purpose |
|---|---|
| `IRANUX_METADATA` | Describes the script as a whole |
| `IRANUX_PARAM` | Describes one user input parameter |
| `IRANUX_CERTIFICATION` | Added only by Iranux Validator after verification |
| `__IRANUX_REACHED_END_V1__` | Runtime marker showing the script reached its final intended point |

---

## 6. Official Block Syntax

Iranux v1.0 uses Bash heredoc no-op blocks.

### 6.1 Metadata Block

```bash
: <<'IRANUX_METADATA'
{
  "standard": {
    "name": "iranux-script-metadata",
    "schema_version": "1.0"
  },
  "script": {
    "id": "install-nginx",
    "name": "Install Nginx",
    "version": "1.0.0",
    "description": "Installs Nginx on a Linux server."
  },
  "risk": {
    "level": "medium"
  }
}
IRANUX_METADATA
```

### 6.2 Parameter Block

```bash
: <<'IRANUX_PARAM'
{
  "name": "domain",
  "label": "Domain",
  "description": "The domain name used by the script.",
  "type": "domain",
  "required": true,
  "example": "example.com"
}
IRANUX_PARAM

DOMAIN="${DOMAIN:-}"
```

### 6.3 Certification Block

```bash
: <<'IRANUX_CERTIFICATION'
{
  "standard": "iranux-certification",
  "version": "1.0",
  "status": "verified"
}
IRANUX_CERTIFICATION
```

`IRANUX_CERTIFICATION` must be generated only by the official Iranux Validator.

Script authors and AI agents must not manually create or modify it.

---

## 7. Block Count Rules

A valid Iranux v1.0 script follows these rules:

| Block | Count |
|---|---:|
| `IRANUX_METADATA` | Exactly one |
| `IRANUX_PARAM` | Zero or more |
| `IRANUX_CERTIFICATION` | At most one |

If a script contains more than one `IRANUX_METADATA` block, it is invalid for Iranux Compatible or Verified validation.

If a script contains more than one `IRANUX_CERTIFICATION` block, it is invalid for Iranux Verified validation.

---

## 8. Required Metadata Fields

Every `IRANUX_METADATA` block must include:

```text
standard.name
standard.schema_version
script.id
script.name
script.version
script.description
risk.level
```

Minimal valid metadata:

```json
{
  "standard": {
    "name": "iranux-script-metadata",
    "schema_version": "1.0"
  },
  "script": {
    "id": "install-nginx",
    "name": "Install Nginx",
    "version": "1.0.0",
    "description": "Installs Nginx on a Linux server."
  },
  "risk": {
    "level": "medium"
  }
}
```

---

## 9. Risk Levels

Allowed `risk.level` values:

```text
safe
low
medium
high
dangerous
```

Suggested meaning:

| Risk Level | Meaning | Example |
|---|---|---|
| `safe` | Read-only or informational | Show system information |
| `low` | Minor low-impact changes | Create a directory |
| `medium` | Package installation or service changes | Install Nginx |
| `high` | SSH, firewall, users, permissions, networking, critical services | Change SSH config |
| `dangerous` | Destructive or highly disruptive operations | Delete data, format disk |

Example:

```json
"risk": {
  "level": "high"
}
```

---

## 10. Optional Requirements Metadata

A script may declare obvious runtime requirements.

Example:

```json
"requirements": {
  "requires_root": true,
  "requires_internet": true,
  "supported_os": ["ubuntu", "debian"],
  "required_commands": ["apt-get", "systemctl"]
}
```

This helps Iranux display useful information before execution.

---

## 11. Parameter Definition

Each user input is defined by one `IRANUX_PARAM` block.

Required fields:

```text
name
label
description
type
required
```

Optional fields:

```text
default
example
placeholder
group
sensitive
options
validation
```

Minimal example:

```json
{
  "name": "server_name",
  "label": "Server Name",
  "description": "A friendly name for this server.",
  "type": "string",
  "required": false
}
```

Complete example:

```json
{
  "name": "http_port",
  "label": "HTTP Port",
  "description": "The HTTP port used by the service.",
  "type": "port",
  "required": true,
  "default": 80,
  "example": 8080,
  "placeholder": "80",
  "group": "Network Settings"
}
```

---

## 12. Parameter Naming Rules

`IRANUX_PARAM.name` must match:

```regex
^[a-z][a-z0-9_]*$
```

Valid:

```text
domain
server_name
install_nginx
api_key
http_port
```

Invalid:

```text
Domain
server-name
server name
1domain
api.key
```

All parameter names in the same script must be unique.

---

## 13. Parameter Grouping

Parameter grouping is handled inside each `IRANUX_PARAM` block using the optional `group` field.

Example:

```json
{
  "name": "domain",
  "label": "Domain",
  "description": "The domain name used by the script.",
  "type": "domain",
  "required": true,
  "group": "Application Settings"
}
```

Iranux should display parameters with the same `group` value under the same section.

There is no top-level `ui.groups` object in v1.0.

## 16. Boolean and Choice Values

Use `bool` only for true logical boolean values:

```json
{
  "name": "enable_ssl",
  "label": "Enable SSL",
  "description": "Enable SSL configuration.",
  "type": "bool",
  "required": false,
  "default": false
}
```

Do not use `bool` when Bash expects exact values such as:

```text
Y/N
yes/no
1/0
A/B
menu numbers
```

For exact script-facing values, use `enum`.

Original Bash prompt:

```bash

```

```bash
: <<'IRANUX_PARAM'

  "name": "install_nginx",
  "label": "Install Nginx",
  "description": "Choose whether Nginx should be installed. The Bash script expects Y or N.",
  "type": "enum",
  "required": true,
  "default": "N",
  "options": [
    {
      "label": "Yes",
      "value": "Y"
    },
    {
      "label": "No",
      "value": "N"
    }
  ]
}
IRANUX_PARAM

```

## 19. Label and Value

For `enum` and `multi_select`:

```text
label = what the user sees
value = what the Bash script expects
```

Example:

```json
{
  "label": "Full Installation",
  "value": "3"
}
```

The user sees:

```text
Full Installation
```

The script-facing value is:

```text
3
```

There is no `value_map` field in v1.0.

---

## 20. Sensitive Values

These types are always sensitive:

```text
password
secret
private_key
```

Iranux should not display sensitive values plainly in:

- UI after entry;
- logs;
- command previews;
- error details;
- execution history;
- reports.

Use `secret` for:

```text
API keys
tokens
access keys
bearer tokens
license keys
machine secrets
```

Use `password` for human-entered passwords.

---

## 21. Non-Interactive Scripts

Iranux Compatible scripts should be non-interactive in the normal execution path.

Instead of:

```bash
read -p "Enter domain: " DOMAIN
```

use:

```bash
: <<'IRANUX_PARAM'
{
  "name": "domain",
  "label": "Domain",
  "description": "The domain name used by the script.",
  "type": "domain",
  "required": true
}
IRANUX_PARAM

DOMAIN="${DOMAIN:-}"
```

The method for passing values into Bash belongs to the Iranux execution layer and is intentionally out of scope for the metadata standard.

---

## 22. Final Execution Marker

Every Iranux Compatible or Verified script must print this marker in the successful normal execution path:

```bash
echo "__IRANUX_REACHED_END_V1__"
```

If the script has a final successful `exit 0`, place the marker immediately before it:

```bash
echo "__IRANUX_REACHED_END_V1__"
exit 0
```

Do not print the marker in failure paths.

The marker means:

```text
The script reached its intended final execution point.
```

It does not mean:

```text
All installation or configuration steps succeeded on every server.
```

---

## 23. Certification Model

Iranux Validator may add an embedded certification block:

```bash
: <<'IRANUX_CERTIFICATION'
{
  "standard": "iranux-certification",
  "version": "1.0",
  "status": "verified",
  "validator": {
    "name": "Iranux Validator",
    "version": "1.0.0"
  },
  "hash": {
    "algorithm": "SHA-256",
    "value": "..."
  },
  "signature": {
    "algorithm": "...",
    "value": "..."
  }
}
IRANUX_CERTIFICATION
```

Certification rules:

- Generated only by Iranux Validator.
- Embedded inside the same Bash file.
- No sidecar certification file is required.
- The script author must not manually write or modify certification.

---

## 24. Hashing Rule

Because the certification block is embedded in the same file, it cannot be included in its own hash.

Therefore:

```text
Certifiable Content = the whole Bash file after removing IRANUX_CERTIFICATION
```

Hashing rules:

```text
Algorithm: SHA-256
Line endings: normalize to LF before hashing
```

## 25. Validator and Runner Responsibilities

### Iranux Validator

The Validator performs full validation and certification.

Responsibilities:

- parse Iranux blocks;
- validate JSON;
- validate required fields;
- validate parameter names;
- validate parameter types;
- validate enum and multi_select options;
- validate default/type compatibility;
- check duplicate parameter names;
- check final marker;
- generate errors and warnings;
- compute hash;
- generate `IRANUX_CERTIFICATION`;
- sign the script.

### Iranux Runner / App

The Runner performs lightweight runtime operations.

Responsibilities:

- detect Plain / Compatible / Verified status;
- read metadata and parameters;
- build the user input form;
- validate user input;
- mask sensitive values;
- verify signature for Verified scripts;
- execute the script remotely;
- stream output;
- detect the final marker.

---

## 26. AI Refactor Agent

An AI Refactor Agent may help convert ordinary Bash scripts into Iranux Compatible candidates.

However:

```text
AI must not verify.
AI must not certify.
AI must not sign.
AI must not generate IRANUX_CERTIFICATION.
```

The AI Agent should only produce:

```text
Iranux Compatible candidate
```

Final verification must be done by the deterministic Iranux Validator.

## 27. Minimal Complete Example

```bash
#!/usr/bin/env bash

: <<'IRANUX_METADATA'
{
  "standard": {
    "name": "iranux-script-metadata",
    "schema_version": "1.0"
  },
  "script": {
    "id": "install-nginx-basic",
    "name": "Install Nginx Basic",
    "version": "1.0.0",
    "description": "Installs Nginx on an Ubuntu or Debian server."
  },
  "risk": {
    "level": "medium"
  },
  "requirements": {
    "requires_root": true,
    "requires_internet": true,
    "supported_os": ["ubuntu", "debian"],
    "required_commands": ["apt-get"]
  }
}
IRANUX_METADATA

: <<'IRANUX_PARAM'
{
  "name": "http_port",
  "label": "HTTP Port",
  "description": "The port that Nginx should use for HTTP traffic.",
  "type": "port",
  "required": true,
  "default": 80,
  "group": "Network Settings"
}
IRANUX_PARAM

HTTP_PORT="${HTTP_PORT:-80}"

apt-get update -y
apt-get install -y nginx

echo "Nginx installation flow reached the end."
echo "__IRANUX_REACHED_END_V1__"
exit 0
```

## 30. What Is Intentionally Out of Scope in v1.0?

Iranux Bash Script Standard v1.0 does not define:

```text
parameter passing strategy
environment variable injection
command-line argument format
stdin format
SSH execution strategy
remote upload strategy
shell escaping implementation
rollback
multi-step workflows
complex dependency graphs
structured final result JSON
post-install success checks
advanced trust chains
```

These may be defined in separate implementation documents or future versions.

## 34. Short Summary

Iranux Bash Script Standard makes Bash scripts understandable to Iranux.

It allows a Bash script to say:

```text
This is what I do.
These are the inputs I need.
This is how each input should be displayed.
This is the type of each value.
This script is compatible with Iranux.
This script reached its final execution point.
This script may be officially verified and signed.
```

The standard is simple by design.

It helps Bash scripts become:

```text
structured
form-driven
machine-readable
user-friendly
validator-friendly
Iranux-ready
```
