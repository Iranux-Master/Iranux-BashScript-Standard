# Migrating Iranux Scripts from v1.2 to v1.3

## Summary

Version 1.3 adds one optional feature: the `dns` member of the metadata, which declares
the DNS records a script needs so the runner can create them in the user's own DNS
(specification v1.3 §5.7). A v1.2 script that needs no DNS record has nothing to gain
from v1.3 and should stay at `1.2`. A valid v1.2 script becomes a valid v1.3 script by
changing the schema version; nothing else changes.

Migrate a script when its description tells the user to point a domain at the server,
when it requests a certificate for a domain over HTTP, or when it answers DNS for a
subdomain (a DNS tunnel).

## Steps

1. Remove any `IRANUX_CERTIFICATION` block. Certification is re-issued after the change.
2. Change `standard.schema_version` from `1.2` to `1.3`.
3. Make sure the domain the records belong to is a parameter of type `domain` (or
   `hostname`) with `required: true`. It is the record's `anchor`.
4. Add a `dns` member with one record per DNS record the script needs:
   - a site: an `A` record `{anchor}` → `{server.ipv4}` and an `AAAA` record
     `{anchor}` → `{server.ipv6}` with `"when": "server.ipv6"`; optionally a `CNAME`
     `www.{anchor}` → `{anchor}` with `"optional": true`;
   - a DNS tunnel on `tunnel_domain`: an `A` record `{anchor.label}-ns.{anchor.parent}` →
     `{server.ipv4}` (the glue) and an `NS` record `{anchor}` →
     `{anchor.label}-ns.{anchor.parent}`;
   - a mail server: `MX` with `priority`, an SPF `TXT`, a DMARC `TXT`, and the DKIM key as
     an `after_run` `TXT` record whose value is `{output.<key>}`, printed by the script in
     its `IRANUX_RESULT` line.
5. Give every record a `purpose` sentence and `i18n.fa.purpose`.
6. Remove from the description the sentence that asks the user to create the records by
   hand; keep a sentence for runners that do not process `dns` (the desktop runner)
   only if it helps.
7. Read `IRANUX_DNS_STATUS` with a default (`"${IRANUX_DNS_STATUS:-none}"`). When the
   script's work depends on the records (a certificate request) and the status is not
   `applied` or `manual`, check the authoritative name servers and retry for a few
   minutes before giving up with exit 75 (specification v1.3 §8.1.2).
8. Remove any parameter that asks for a DNS account token, together with the code that
   used it to create records, now that the records are declared (warning IRX2014). This
   changes behaviour on runners that do not process `dns`; say so in the change notes.
9. Run `python3 tools/check_fixtures.py your-script.sh` and, for a catalog,
   `--profile catalog`.

## What stays the same

Parameters, the result line, certification, the final marker, risk levels and every
v1.2 rule. A `dns` block does not raise the risk level by itself; a DNS tunnel that binds
port 53 is `dangerous` because of what it does on the server.
