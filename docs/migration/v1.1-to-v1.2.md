# Migrating Iranux Scripts from v1.1 to v1.2

## Summary

Version 1.2 adds optional fields for non-expert users (Persian text, basic/advanced
parameters, generated values, a structured result, an estimated run time) and
completes rules that v1.1 left open or stated differently from what the Iranux runner
does. A valid v1.1 script becomes a valid v1.2 script by changing the schema version;
everything else in this guide improves the script for the web application.

## Steps

1. Remove any `IRANUX_CERTIFICATION` block. Certification is re-issued after the
   change.
2. Change `standard.schema_version` from `1.1` to `1.2`.
3. Add `script.estimated_minutes` (1–240).
4. Add `script.i18n.fa` with `name` and `description` in Persian (specification §6).
5. For every parameter:
   - add `i18n.fa.label` and `i18n.fa.description` (and `placeholder` when the English
     one is not an identifier the user would recognise);
   - decide `level`: keep as basic what a non-expert must decide; mark tuning values
     with sensible defaults `"level": "advanced"`. An advanced parameter that is
     `required` needs a `default` or a `generate`;
   - add `generate` where the platform should create the value: `password` for an
     admin password, `port` for a panel port, `uuid` for an identifier. Keep the
     script's own fallback for runners that do not generate;
   - rewrite descriptions for the end user. "The Bash script expects Y or N" becomes
     "Choose whether …"; the `enum` options carry the Y/N values;
   - check that the script reads the parameter as `"${NAME:-default}"` with the same
     default as the block, and that every expansion is quoted.
6. Print one `IRANUX_RESULT` line before the final marker with what the user needs
   afterwards: the address to open, the username to type, a file path; list generated
   secrets in `show_generated` instead of printing them.
7. Check `requirements.supported_os` against the `/etc/os-release` identifiers of §11
   (`ol`, not `oracle`; no version numbers), and `requires_root`, `requires_internet`.
8. Check `risk.level` with the decision rule of §12. Scripts marked `dangerous` are
   refused by the Iranux web platform unless an administrator allows them. By the
   table of §12 a panel or tunnel installer that installs packages and its own service
   is `medium`; it is `high` when it also opens firewall ports beyond its own, edits
   `sshd_config` or adds users, and `dangerous` only when it replaces system services,
   resets the firewall, changes SSH access or removes data it did not create.
9. Replace exit codes with the table of §8.4 where the script exits for a known
   reason (64 invalid input, 69 download failed, 77 not root, 78 unsupported OS).
10. Make sure the final marker is on its own line, printed only after all work and
    after the result line, on every successful path.
11. Run the Validator (or `tools/check_fixtures.py` for a quick schema check), `bash -n`
    and `shellcheck`. Request certification when required.

## Corrections to v1.1 that affect existing scripts

| v1.1 said | v1.2 says | What to do |
|---|---|---|
| The certification block is `{"standard","version","status"}`. | The block has the seven fields the runner reads (§13.2). | Nothing for authors; never write the block. A block in the old form makes a script Invalid in the runner. |
| `supported_os` has `minItems: 1`. | An empty list is allowed and means "any Linux"; the runner already accepted it. | Keep lists accurate; use `ID` values (`ol`, `amzn`, `opensuse-tumbleweed`). |
| Option `value` may be any JSON value; options have no `description`. | `value` is a non-empty scalar without `,`; `description` is allowed. | Remove object or array option values; `multi_select` values must not contain commas. |
| `validation` is any object. | Five keys: `min_length`, `max_length`, `min_value`, `max_value`, `pattern`. | Remove other keys; the runner ignored them. |
| The marker rule is "print `echo "__IRANUX_REACHED_END_V1__"`". | The marker is alone on its line, after the result line; the static check is the regular expression of §8.5. | Check that no other text shares the marker's line. |
| `firewall` is a recommended icon (`docs/implementation/mdi-icon-validation.md`). | `firewall` does not exist in Material Design Icons; `wall-fire` and `security-network` do. | Replace `firewall` where used. |
| `samples/v1.1/` and `tests/invalid/` are listed. | The folders are `Samples/v1.1/` and `tests/invalid/` (now populated). | Nothing. |

## What must not change automatically

A migration or conversion tool must not:

- rewrite the Bash logic, change package managers, service names or exit paths;
- add `set -euo pipefail` to a script that did not have it;
- add runtime checks the script did not have, except the quoting of parameter
  expansions and the `${NAME:-}` form, which the specification requires;
- invent download URLs, versions, checksums, icons or operating-system support;
- translate by changing meaning: the Persian text says what the English text says;
- create or edit `IRANUX_CERTIFICATION`.
